# Reading requirements

## Library and original books

Import via Android document picker and ACTION_VIEW/ACTION_SEND readable content URI. EPUB only. Copy the original archive to app-private files; metadata, covers and reading order come from Readium. Do not flatten chapters into new plain-text books or implement another paginator. Show import failure without adding a corrupt library entry. Clean up files created by failed imports. File reads are bounded; never log source URI tokens or private passages. EPUB scripts must not execute app capabilities.

Display actual title, author and cover where available; a generated typographic cover is an honest fallback. Find books by title/author. Removal requires confirmation, removes local book/cover/location/time data, and does not modify the original external file.

## Web page import

The add control offers a file or an https link, and an ACTION_SEND text share carrying a link opens the same import flow through a dedicated share activity; cleartext http is refused because the app's network security config forbids it, so a promise to load it would be false. A link is first fetched directly; when that response is not clearly the article — a non-200 status, a non-HTML body, too little text, or a bot-challenge marker — the app loads the page in its own browser instead. The browser uses the reader's network and login state, so a challenge or an account wall can be completed by hand before importing, and nothing is fetched by a server.

Conversion stays local and generic: the vendored pipeline extracts the article with Mozilla Readability and assembles an EPUB. The host adapter preserves rendered descendants of `display: contents` containers without changing vendor files. Both automatic and manual capture reject short preview cards, sign-in walls and unavailable-page shells rather than saving them as successful books. An explicit call to continue with the full article (for example “Continue reading”, “Read the full article” or 阅读全文) is a preview refusal even when the rendered excerpt already exceeds the length threshold; generic “Read more” footers and reading-time labels do not block a complete article. A discovered full-article link may be followed once on the same HTTPS origin; inaccessible content remains an explicit failure, never invented text. Currently captures shorter than 500 normalized characters are refused, so this importer is for articles rather than short social posts. Generated EPUBs enter the ordinary importer; no separate web reader or per-site scraping framework is introduced.

Imported articles retain their stated headline and author. Existing converter metadata takes precedence; a missing author may be recovered from a byline or card title corroborated by the page's stated author profile. A profile URL or handle alone is not a display name, and missing or conflicting evidence leaves the author empty. Existing imported archives are not rewritten; reimport to obtain newly recovered metadata.

## Reading and restoration

Use Readium navigation and supported EPUB preferences. New reading preferences use the system font; the font chooser offers System font first, followed by five bundled, OFL-licensed families: Literata, Source Serif 4, Noto Serif, Atkinson Hyperlegible and Source Sans 3. Explicit saved font choices are retained. System font delegates to Android WebView's platform typography; a manufacturer's downloadable font affects it only if that WebView honors the system customization. Legacy serif/sans preferences resolve to real bundled equivalents, with system CJK fallback. Font size, letter spacing in em, line height, paragraph spacing and margins must affect rendered text and persist across restarts. Font-size percentage is translated to Readium scale units. Independent top/bottom text distances remain configurable. Typography applies only typography fields against current settings, never overwriting reading-option changes from a stale draft.

Immersive reading is one persistent option, enabled by default. Enabled hides system status/navigation bars, temporarily revealable by edge swipe; disabled retains normal system bars. Reading controls start hidden. Center tap shows or hides the overlay tools without stopping narration, changing navigator dimensions, repaginating or invoking page navigation. Text and images stay at the same position even deep in long chapters. Back dismisses lookup/panels before hiding controls or leaving.

The accepted A layout has four overlay menu entries: Contents, Layout, Features and Listen (目录 / 排版 / 功能 / 朗读). While narration is active, the menu stays available and an expanded floating card above it offers previous sentence, play/pause, next sentence, speed, stop and retry. Collapsing the menu replaces that card with only previous/play-pause/next centred against the whole screen; the single page counter stays at the left. X ends narration and leaves the normal menu visible. No control creates a hidden spacer or changes book measurement. Layout opens typography; Features groups immersive reading, continuous scrolling, Quick Explain and auto-pronounce. Their switches are not duplicated in global Settings or typography.

A passive chapter label stays at the top-left and one page counter — the page within the whole book and the book's page total for the current layout — at bottom-left in paginated reading. A chapter counter is not shown beside it: one corner carries one meaning, chapter pacing belongs to the contents, and the chapter name already heads the page. The label shows the actual current chapter title, falling back to the publication's table-of-contents and reading-order titles when the locator supplies none, updates when the chapter changes, shortens long titles instead of overlapping the page, and remains visible while chrome is hidden. Because these labels live in the narrow band reserved outside the book text, their own text scaling is capped so they cannot grow onto the first line, while book text keeps scaling normally. Counts update after reflow and never become stored reading positions. Readium paginates one resource at a time, so the counter is derived: a chapter of at least five pages gives the layout's characters-per-page density, which converts the text before the current resource into pages before adding the exact page within it, and converts the publication's character total into the book total. The density is cached per layout signature (font, spacing, margins, insets, viewport) in display-only preferences, so a short chapter or a restart still shows the counter; it is recomputed whenever the signature changes. Chapters shorter than five pages never teach the density because their first and last pages are partial. The counter therefore changes with the layout, as reflowable page numbers always do, and no chapter count is ever presented as the book total. Resource file names are never shown as chapter names, even when the table of contents or the reading-order link supplies one. Scroll mode shows honest chapter/progression information rather than claiming a fixed page count. Passive labels do not intercept gestures. Controls remain legible across all themes and focus/keyboard transitions.

Persist Readium locator JSON for each book. Progress percentages and page counts are display derivatives, never restoration identifiers. Persist position serially and flush on background/exit. Restoration passes the persisted locator into navigator creation; initial callbacks must not overwrite it with a default first-page location.

Remember the last successfully opened book. On a new app launch, reopen that book directly at its saved locator. Returning intentionally to Library during the same session must not immediately reopen it. A missing/deleted/unreadable last book falls back to Library with a clear explanation, not a launch loop. No books means Library. Rotation and process recreation must not restore stale runtime page indexes. Model setup and popup dismissal never change reading position.

## Continuous read-aloud

Listen starts continuous narration from the current page's first visible block, independent of an earlier search or selection. Long-press selection offers Explain, Dictionary and Copy only; narration is not a selection action or a duplicate Features entry. Narration continues sentence by sentence, with the current sentence plus at most two following sentences as bounded lookahead rather than a chapter burst. Each complete sentence is one generation/cache unit. Pause retains the playback time within that clip; resume seeks to that time before playing instead of replaying the prefix. A lookup that interrupts active narration resumes on close, but a prior manual pause remains paused. Navigation, skip, retry, stop and session replacement invalidate old resume intent. A MediaSession supports screen-off playback and system controls.

Online narration uses Microsoft's public, key-free read-aloud service only, requested for the reader's US or UK accent. It is undocumented and unendorsed: availability and quality are not guaranteed and it may change. Narration does not retry Baidu and never falls back to system speech; if the service supplies no complete audio, playback stops with an explicit, localized error and an offered retry rather than silently speaking with another voice. A provider request carries at most 190 characters, so a long sentence is assembled from contiguous chunks, and its cache key and playback unit remain the complete sentence. A sentence that needs more than 16 such chunks is refused explicitly, never truncated.

Sentence audio is stored in app-private, no-backup storage with opaque SHA-256 names, validated complete MPEG frames, a 16 MiB per-sentence ceiling and a 4 GiB least-recently-used total bound. A sentence heard before, including a repeated occurrence elsewhere, reuses the same cached clip; cached sentences still play after a process restart and with the network offline. The quota is a cache limit, not a lifetime: clips have no expiry, and byte accounting is initialized once and trimmed in a batch only when a write crosses the bound. Reader Options shows the current cache size and a clear action; Settings also shows cache usage and a separate manual clear. Clearing stops active narration first and removes only narration audio. Popup word and example pronunciation keeps its separate memory-only lifetime and its own fallback chain.

## Search

Contents contains a binoculars entry for searching the opened publication's complete text, not just chapter names. Search Back/Close returns to Contents. The query field and its action stay fixed while real results scroll independently. Each full-width result shows matched text in a bounded snippet and the chapter resolved through the same resolver as the reader label; unknown chapters remain unnamed. Selecting a result navigates to its actual locator. Empty, running and failed searches report their own honest state.

## Statistics

Persist daily reading-time increments per book. Count only foreground reader time while the user interacted within two minutes; periodic flush at most 60 seconds plus lifecycle/exit flush. Use monotonic time for elapsed time and local calendar dates for aggregation. UI: today, current week (Monday start), cumulative time; recent 7/30 days and recent books with accumulated time. Empty data shows an empty state. No historic backfill or fabricated estimates. Book deletion removes its time records. Popup lookups count as interaction, not separate learning statistics.
