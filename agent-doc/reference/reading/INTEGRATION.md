# Reader integration

Code paths are relative to `app/src/main/java/app/margin/reader/`.

Last-book reopening is a cold-entry decision. Initial navigator construction uses the stored locator; persisted progress is never replaced by a guessed page index. Screen state and saved publication location are different lifetimes.

`reader/ReaderActivity.kt` deliberately disables automatic Fragment snapshot restoration with `super.onCreate(null)`. It opens the publication and constructs the navigator with the durable locator instead of restoring a transient page-index tree. Publication resources close only after Fragment view teardown. Preserve that restoration boundary when changing Activity or navigator lifecycle handling.

`reader/PublicationContentPolicy.kt` owns publication-content security. A public Readium container/resource transform serves sanitized HTML with a local-only Content Security Policy before Readium injects its trusted scripts. Original archives are unchanged. Authored executable content and automatic remote resources are excluded; explicitly activated external HTTP(S) links remain browser actions.

`reader/NavigationSafety.kt` owns decoded fragment validation across publication links, restored locations, search/TOC navigation and served internal links. The pinned navigator interpolates HTML IDs into native JavaScript, so unsafe string-literal characters must not reach that interface.

`reader/ResourceFailurePolicy.kt` distinguishes fatal HTML spine failures from optional image/font/stylesheet failures. An optional resource failure must not erase last-book recovery or close an otherwise readable book.

`reader/ReaderChromePolicy.kt` owns visibility, center-tap ownership, Back precedence and system-bar interpretation. `ReaderActivity` hosts the unmodified navigator in a full-size Box with stable system/cutout insets. `ReaderChrome` and `ReaderCompactNarration` are overlay siblings, never measured book space. The expanded chrome contains its top bar, four-entry menu and optional narration card; compact transport is centred independently of the left page label. Only actual control bounds consume touches, leaving surrounding page gestures to Readium. Chrome changes do not need viewport restoration; the obsolete dynamic-height transaction and retention code are removed.

`reader/ReaderFonts.kt` owns the system option, five bundled families and Readium font-face declarations. The system option has no packaged faces and uses unquoted `system-ui, sans-serif` in the root CSS override; only bundled entries register font-face declarations. `ReaderPreferences.kt` translates persisted typography into Readium preferences and includes resolved font identity plus letter spacing in the layout signature. `PublicationContentPolicy` allows only the local packaged font path for these faces, without opening script/connect permissions. `ReaderSheets.kt` renders typography and behavior separately; `ReaderControls.kt` applies only the fields owned by each sheet against current settings. `reader/ReaderViewport.kt` keeps native top/bottom text distances stable; Readium owns horizontal margins and typesetting.

`narration/NarrationService.kt` owns the narration publication and Readium TtsNavigator independently of the visible Activity. The fourth menu action starts it from the current first visible element, never a stale search match. The Activity binds while started, follows utterance locators for page/highlight updates, and never owns audio. The service persists the narration locator as reading position. Selected-text actions no longer need selection-rectangle positioning or a separate narration anchor.

`NarrationPlayback.kt` prefetches only after the current sentence starts, bounded to two sentences or about fifty words, and one shared provider gate keeps synthesis sequential across session switches. Readium's pause is a cancelled speak followed by `TtsEngine.stop()`, so `NarrationEngine.kt` samples `MediaPlayer.currentPosition` before release and seeks the same cached clip after re-preparing it; resume never re-synthesizes that sentence or replays its prefix. A per-session `NarrationResumePolicy` scopes that checkpoint to the current reading intent: next/previous/seek/retry/stop/end/new session invalidate it, while a speed change keeps it. The same policy owns lookup pauses: `Binder.pauseForLookup()` pauses only active playback and `resumeAfterLookup()` resumes only the still-current utterance that lookup paused, never a manual pause or a user navigation. `NarrationEngine.kt` plays only the cached clip the synthesizer produced; failure is typed and localized, with no second online route or device-speech fallback. `SentenceAudioCache.kt` owns the no-backup `sentence-audio` directory, opaque SHA-256 names, complete-frame validation, atomic replacement and a 4 GiB LRU bound. Usage is initialized from the directory once and maintained under the cache mutex; only a write that crosses the bound enumerates and sorts clips, and that trim removes a 5% batch so ordinary writes and hits never scan the directory. Clear is serialized behind the provider gate after narration stops.

`reader/ReflowAnchor.kt` captures the visible text range before a typography change, rather than the start of a long containing paragraph. The probe resource must match the native locator resource; a pending chapter transition defers the change until their identities agree. Current chapter and current/total chapter pages come from navigator callbacks and are passive overlays, never persisted progress. `reader/ChapterTitles.kt` resolves a locator's real chapter name when the locator itself carries no usable title. A titled part names the untitled chapters beneath it through the table of contents' own hierarchy; a named chapter never lends its name to a sibling or to another file, and an ambiguous or untitled position stays blank rather than being invented. `ChapterTitles.of(tableOfContents, readingOrder)` builds the index once per publication and `titleFor(locator)` prefers this publication's table-of-contents title for the locator's resource — matching authored hrefs before normalizing fragments, queries and directory-only prefixes, and accepting a shortened entry only when it resolves to exactly one reading-order resource — then falls back to the spine/reading-order link title. It feeds the passive label, the chapter name sent with a lookup and the chapter line of each search result; an unknown chapter stays blank rather than invented, the resolver only collapses and trims whitespace, and the resolved label is display state only that must not be written back to the stored locator.

`ui/BookSearchDialog.kt` owns search presentation: a fixed query field and status with independently scrolling results, and full-width rows built from the reader's resolved chapter title for that match — the same resolver as the top-left reading label, not a bare locator title — plus a match-centred snippet (whitespace collapsed, bounded context on each side, the match emphasised) instead of rendering a whole publication paragraph inside a button. The reader Activity owns query state, the Readium search iterator and paging, and opens a row's locator through the same safety validation as any other publication location.

Publication input bounds are owned by `reader/EpubImporter.kt`; they are checked against actual archive/resource bytes.
