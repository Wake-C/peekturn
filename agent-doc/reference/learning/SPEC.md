# Learning requirements

## Selection context

Exact selected word or phrase is the target. Use Readium selection locator text.before/highlight/after and available book/chapter titles. Trim before to its last 30 whitespace-delimited words and after to its first 30; each source snippet remains limited by what Readium provides (approximately 200 characters per side in the inspected implementation). Sixty surrounding words is a ceiling, not a guaranteed minimum. Readium joins the block text it can reach, so a heading and its paragraph arrive glued; each side is therefore collapsed to single spaces and cut back to its nearest sentence edge, keeping at least two words, before it is sent to the model. No full-paragraph reconstruction, chapter parsing, or text search for another occurrence of the word. Missing context is allowed and must not be invented.

With Quick Explain off, normal selection offers Explain, Dictionary and Copy, with no read-aloud selection action. Quick Explain is a global persisted preference, default off: when enabled it suppresses the floating action menu while retaining the native highlight and handles, and explains a newly established selection after gesture release. No popup, model request or automatic pronunciation starts while the initial selection or a handle drag is held. The final native range is the target, not an intermediate word. Adjust closes/cancels the popup while preserving the source selection and handles in both modes. With Quick Explain on, a revised released selection may request once; with it off, Explain remains explicit. Repeated adjustment must not duplicate automatic requests. Popup close clears selection; navigation clears lookup and cancels work.

## AI explanation

Readers can save named OpenAI-compatible model profiles containing base URL, model identifier, API key and temperature, then switch the active profile without re-entering credentials. Temperature is a finite number from 0 to 2, default 0.3, sent on both connection tests and explanations. It controls randomness, not response speed; provider/model support varies. There is no separate reasoning switch or request override. Invalid drafts cannot be saved or tested. Create/edit/delete/select are local configuration operations, not automatic provider failover. Existing configurations migrate without losing keys. Keys remain Android Keystore-encrypted per profile, absent from generic settings JSON, logs and backups. Missing credentials do not prevent reading or offline dictionary lookup.

App-owned instructions request term, partOfSpeech, ukIpa, usIpa, meaning, context and examples. Explanation language follows the effective Activity locale, including Follow system. English requests “elementary English for meaning and contextual explanation”, using common everyday words and short direct sentences without difficult grammar labels; this is a generation goal, not a certified reading level or a client-side word-count filter. Chinese retains its dedicated original Simplified Chinese prompt for meaning and contextual explanation. Examples are one or two complete objects `{text, translation}`: text remains English, with required corresponding Chinese translations in Chinese mode and empty translations requested in English mode. Repeated root fields and examples beyond the two-example limit are invalid. IPA and selected terms remain unchanged. Source text and titles are quoted user data, never system instructions; no full-passage translation or custom-prompt editor.

Request schema-constrained structured output when supported. JSON mode is a compatibility option inside the client, not a promise that any provider supports strict schemas. Validate response fields; no regex guessing of a different answer. Support streamed content and progressive complete fields, keep reasoning separate, and never expose raw JSON or incomplete example text as playable content. Refusal, empty answer, malformed output, HTTP errors, EOF without terminal completion, and token truncation are errors. Every failure carries an app-owned category — configuration, authentication, quota, connectivity, malformed output, incomplete output, refusal or provider rejection — that the interface localizes into actionable copy in both English and Chinese; raw provider text never reaches the UI. Keep useful validated partial content labelled incomplete. Retry is explicit and uses latest saved configuration with the original context. Dismiss/leave/new selection cancels the request and ignores old callbacks. Do not add automatic charge-incurring retry loops.

The explanation surface is bottom-docked, retaining the same focusable popup and content/request lifecycle. It grows upward within safe window bounds as complete streamed fields arrive, rather than choosing a short side of the source selection. It leads with meaning, then contextual meaning and one or two examples; source book snippets are not displayed. The fixed header keeps selection, preferred IPA/part of speech and term speaker. Tabs and close/adjust remain reachable while long/error/partial answers scroll independently. Speaker, stop, fallback notice and playback failure feedback stay in the popup, but the popup does not render the current audio provider's credit; that disclosure remains in Settings → Pronunciation. Example speakers use the existing [pronunciation routes](../pronunciation/SPEC.md). This container change does not change prompts, response schema, clipping, validation or example formatting. Closing a lookup stops its pronunciation before allowing an owned narration pause to resume; Adjust/navigation/lifecycle dismissals do not auto-resume.

Successful explanations are reused from an app-scoped private cache for 15 days after successful completion. Reuse requires the exact request identity: the provider-clipped selection and before/after context, book id, chapter resource key, book/chapter titles, explanation language, profile id, endpoint, model and temperature. If Readium supplies neither preceding nor following context, the answer is still shown for that lookup but is never reused from memory or disk: without a stable occurrence locator a word-only key could smear one occurrence's answer onto another. A different sentence, chapter, book, language or provider configuration is a different entry, and switching language can never show an answer in the previous language. Reads never extend the absolute 15-day lifetime. The store is bounded to 1 GiB with a 512 KiB per-record ceiling and keeps only complete validated answers; failures, partial objects and malformed records are never reusable. AI/Dictionary tabs preserve same-lookup work instead of repeating a paid request; explicit Retry bypasses reuse and replaces the older entry. Examples become visible/playable only once a complete validated object is available, and their speaker receives only the English text, not the Chinese translation. Leaving the reader ends in-flight session work but not the persisted cache. Settings shows cache usage and offers a manual clear, which advances a generation so an in-flight completion cannot repopulate it.

Explanation prompt generation is language-specific and is part of both the request/cache key and the persisted record gate. The revised English prompt uses generation v2, so old, more advanced English explanations cannot mask the new policy after an upgrade. The unchanged Chinese prompt retains generation v1 and can reuse its existing Chinese answers. Existing books, settings and provider credentials are not cleared.

## Dictionary

Bundle a real offline English dictionary with verified upstream attribution. Lookup runs off the UI thread; normalize whitespace/case. Show available phonetic/part-of-speech/meaning fields. Missing entries and unsupported queries have honest states. Dictionary is a secondary explicit action, never a silent substitute for an AI response. Asset and first-use extraction must work without network.
