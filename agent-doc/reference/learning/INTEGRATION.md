# Learning integration

Code paths are relative to `app/src/main/java/app/margin/reader/` unless they name a repository-level file.

`learning/ExplanationClient.kt` owns provider requests, structured-output compatibility and clipping Readium's selected-text snippets to the [product context window](SPEC.md#selection-context). Requests to `api.openai.com` use strict JSON schema mode; other hosts, including DeepSeek and custom compatible endpoints, use JSON object mode. Both paths require application validation; host selection does not guarantee model support.

Reader-Activity-owned `learning/LearningSession.kt` owns in-flight work and bounded successful-answer reuse, and closes when that Activity is destroyed. Cache identity includes source selection/context and active profile/configuration. Dictionary presentation does not restart model work. Popup dismissal ends unfinished lookup work; completed answers survive within the same reader session. Explicit Retry bypasses reuse; failures do not become successful cached answers.

`reader/SelectionSession.kt` owns the native selection lifetime and the actual gesture boundary: the pointer's hold start and end, the token that owns asynchronous native reads, the selection each release ended with, and the identity already explained. Automatic explanation is eligible only for a release the app actually observed, and only for the identity that release read recorded when it is usable and is not the one already explained, so a held pointer, an obsolete read, a selection that never finished its gesture or an unchanged selection can never start a request; the observed release is the boundary, not an elapsed delay. Because Readium's release-time read is an asynchronous WebView round trip, the released selection is read under a bounded budget: only repeated reads that agree count as confirmed, a native range that keeps moving is unconfirmed, an empty read means nothing is selected, and a read that never answers is unavailable. Automatic explanation acts only on a confirmed range, so an unconfirmed, empty or unavailable release records no released range at all. Two invariants hold: an automatic explanation may only use the identity recorded for the released gesture, so once that identity is recorded no later read can substitute a different one, and every read is re-validated against the gesture token and pointer state before it can be used, with any newer gesture, session, page or popup cancelling it. Adjusting keeps the native selection while the recorded explained identity prevents reopening the old highlight. The physical pointer lifetime is separate from selection state: the hold start and end follow the real touch stream, `cancelGesture` (reader pause) is the only lifecycle reset, `clear()` bumps the session token and drops the released/explained state without ending a held gesture, source input may end the session only with the pointer up, and a debounced location change cannot clear a selection that a held gesture still owns. Explicit Explain, Dictionary and Copy always resolve the live native selection and never act on a remembered range: they use the same bounded, token- and pointer-validated read, accepting a confirmed or unconfirmed live range, and an empty or unanswerable read reports a truthful message while leaving the native selection intact. The range recorded when the gesture was released only gates automatic explanation.

Dictionary packaging uses a `.dict` extension to preserve precompressed gzip bytes through Android asset packaging. `tools/build_dictionary.py` owns rebuilding; the [dictionary notices](../../../THIRD_PARTY_NOTICES.md#ecdict-offline-dictionary) own provenance and rebuild instructions.
