# Pronunciation integration

Code paths are relative to `app/src/main/java/app/margin/reader/`.

Application-scoped `speech/PronunciationPlayer.kt` owns latest-only audio and system-speech playback, cancellation and audio focus; screen lifecycle events stop playback without disposing the shared player. A request that is not a single word — a selected phrase or a generated example — tries the Microsoft sentence-speech client first, then the Baidu fallback, then installed English speech; a word tries word audio, then the same Microsoft client, then Baidu, then installed English speech. A fallback route never changes what is spoken: the requested word, phrase or example is spoken as the reader asked for it, and only the dictionary lookup for the validated single word ever reaches the word-audio service, never a phrase or example. Accent is a preference, not a playback gate; wrong-language voices remain unavailable, and Baidu's single English voice means its answers substitute for the requested accent, which the player announces instead of claiming the preference was met. Every online service states no creator and no licence, so the app credits whichever one played by name and link only; the [notices](../../../THIRD_PARTY_NOTICES.md#online-word-audio) document the word-audio service and the [speech notices](../../../THIRD_PARTY_NOTICES.md#online-sentence-speech) the sentence services, including unofficial status and Peekturn's lack of permission.

Continuous narration is not owned by `PronunciationPlayer`. `narration/NarrationService.kt` and `NarrationPlayback.kt` own a Readium TtsNavigator, a shared synthesis gate and a persistent `SentenceAudioCache` under no-backup app storage; the reader's Listen action starts it and expanded/compact overlay controls drive it. Opening a lookup pauses narration through `Binder.pauseForLookup()` only while it is playing, and dismissal stops popup word/example audio before `Binder.resumeAfterLookup()` can continue the same sentence at its paused offset; manual pause/play and navigation cancel that lookup ownership. Narration calls `BingSpeechClient` only: no Baidu retry and no system-speech fallback. Cache entries are complete sentences keyed by an opaque SHA-256 of the voice configuration and canonical sentence, validated as complete MPEG frames, bounded to 16 MiB per sentence and 4 GiB in total. Popup word/example audio remains memory-only and never reads or writes that cache.

`speech/WordAudioProvider.kt` owns the public word-audio request: one bounded, key-free HTTPS GET per word carrying only the validated plain word and its accent parameter, with connect/read/call timeouts, a 2 MiB response ceiling, and MPEG-frame validation before anything reaches the decoder. Redirects are not followed, so a redirect answer counts as no audio and the word is never resent to whatever host the redirect names. Unavailable, redirected, oversized, malformed or unexpected answers all mean "no audio", so the player moves to the next route instead of reporting a failure. The native decoder consumes bounded memory through a data source over the in-memory response, not an uncontrolled network address, and no downloaded audio is persisted. The shared `ui/AudioAttribution.kt` credit names and links that provider and nothing else, because it states no creator and no licence. Word-audio callbacks require both request generation and the actual player identity; failure of an obsolete TTS initialization cannot invalidate a word-audio request. Falling back from one route to the next retains the same request's granted audio focus.

`speech/BingSpeechClient.kt` owns the primary sentence-speech request behind the `SentenceAudioSource` interface: one bounded, key-free WebSocket handshake to `wss://speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1`, Microsoft's read-aloud service, the same one Microsoft Edge uses. The handshake carries `TrustedClientToken`, a `Sec-MS-GEC` token computed locally by `speech/BingToken.kt`, its announced version and a fresh `ConnectionId`, with an Edge user agent and the Edge read-aloud extension origin — the request shape this endpoint answers, not a licensing claim, and no key, account or permission is sent or held. It then sends a config frame selecting `audio-24khz-48kbitrate-mono-mp3` and an SSML request naming `en-US-AriaNeural` or `en-GB-SoniaNeural` for the accepted `en-US` or `en-GB` locale, and collects audio frames up to the shared 2 MiB ceiling until the service ends the turn. Text longer than 190 characters and any locale other than US or UK English are rejected before a request is made, so an over-long example never leaves the device. A failed handshake, a rejected or refused token, a frame that is not audio, the byte ceiling, the per-attempt lookup budget (about four seconds) and socket errors all mean "no audio" rather than a failure, and the socket is closed on every path including cancellation. A 401/403 that carries a server Date header is retried once against the same host with a token derived from the server's clock, and the measured skew is reported, because a wrong device clock is otherwise invisible. The service has changed this handshake before — a plain SHA-256 token is now refused with HTTP 403 — which is why a second key-free route and installed speech sit behind it. `speech/BingToken.kt` is this project's own Kotlin implementation of the published token algorithm: no third-party code is vendored and no licence, creator or availability claim is made for the service. `speech/BaiduSpeechClient.kt` owns the second, key-free fallback behind the same interface: one bounded HTTPS GET to `https://fanyi.baidu.com/gettts` with `lan=en`, `spd=3`, `source=web` and `text=` the exact text, with the connect/read/call timeouts, 2 MiB ceiling read before allocation, MPEG-frame gate, refusal of redirects and coroutine-tied cancellation the word client also uses. It has a single English voice, so the clip it supplies carries the explicit caveat that the requested accent is not guaranteed. The player tries the sentence routes in the order `defaultSentenceSources` lists them — Microsoft, then Baidu — each with its own bounded attempt, and installed English speech after both. All three online clients return the same in-memory `AudioClip`, carrying the bytes, the credit of the service that supplied them and any caveat that belongs to the clip, and none persists or caches audio. One internal notice string in `speech/WordAudioProvider.kt` covers every online route and states that system speech is being used when none has answered, so no path reports a missing engine for what is only an unavailable service.

`speech/SpeechDiagnosis.kt` owns the honesty of the device-speech attempt. `configureSpeech` records each engine's answers — whether it listed any voices and what each language probe returned — as the attempt runs, and only a request that ends without a speaker reads them back, so a successful play never shows a report. The reader-facing message and the report's last word come from the same classification, so a failure cannot name a cause the app never observed: an engine that never started, one that offered no English voice, one that reports its English data missing and one that accepted the English text and then failed to speak it (a playback failure, not a missing voice) stay distinct, and "not installed" is claimed only when an engine itself answers `ERROR_NOT_INSTALLED_YET`. When voices and language probes both fail, `substitutedDeviceVoiceNotice` allows one final attempt with the engine's own voice, no voice and no language selected and only for text whose letters are all Latin script, carrying the substituted-voice notice — but only once every engine has declined, so a real English voice on any engine is preferred over a substituted one and a non-English selection never reaches it. An engine that still cannot speak in that pass yields to the next engine of the final pass before the classified failure is reported. The report is shown under the error with a copy action and never on a successful request.
