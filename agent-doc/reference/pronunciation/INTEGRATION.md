# Pronunciation integration

Code paths are relative to `app/src/main/java/app/margin/reader/`.

Application-scoped `speech/PronunciationPlayer.kt` owns latest-only audio and system-speech playback, cancellation and audio focus; screen lifecycle events stop playback without disposing the shared player. A request that is not a single word — a selected phrase or a generated example — tries the sentence speech source first and falls back to installed English speech; a word tries word audio, then the sentence speech source, then installed English speech. A fallback route never changes what is spoken: the requested word, phrase or example is spoken as the reader asked for it, and only the dictionary lookup for the validated single word ever reaches the word-audio service, never a phrase or example. Accent is a preference, not a playback gate; wrong-language voices remain unavailable. Both online services state no creator and no licence, so the app credits whichever one played by name and link only; the [notices](../../../THIRD_PARTY_NOTICES.md#online-word-audio) document the word-audio service and the [speech notices](../../../THIRD_PARTY_NOTICES.md#online-sentence-speech) the sentence one, including unofficial status and Margin's lack of permission.

`speech/WordAudioProvider.kt` owns the public word-audio request: one bounded, key-free HTTPS GET per word carrying only the validated plain word and its accent parameter, with connect/read/call timeouts, a 2 MiB response ceiling, and MPEG-frame validation before anything reaches the decoder. Redirects are not followed, so a redirect answer counts as no audio and the word is never resent to whatever host the redirect names. Unavailable, redirected, oversized, malformed or unexpected answers all mean "no audio", so the player moves to the next route instead of reporting a failure. The native decoder consumes bounded memory through a data source over the in-memory response, not an uncontrolled network address, and no downloaded audio is persisted. The shared `ui/AudioAttribution.kt` credit names and links that provider and nothing else, because it states no creator and no licence. Word-audio callbacks require both request generation and the actual player identity; failure of an obsolete TTS initialization cannot invalidate a word-audio request. Falling back from one route to the next retains the same request's granted audio focus.

`speech/TranslateSpeechClient.kt` owns the public sentence-speech request behind the `SentenceAudioSource` interface: one bounded, key-free HTTPS GET per request to `https://translate.google.com/translate_tts` with `ie=UTF-8`, `client=tw-ob`, `tl=` the accepted `en-US` or `en-GB` locale, `q=` the exact text, an `audio/mpeg` accept header and a plain browser user agent, which is what this endpoint answers — a request shape chosen for the endpoint, not a licensing claim. Text longer than 190 characters and any locale other than US or UK English are rejected before a request is made, so an over-long example never leaves the device. The 2 MiB ceiling read before allocation, MPEG-frame gate, connect/read/call timeouts, refusal of redirects and coroutine-tied cancellation mirror the word client; unavailable, redirected, oversized, malformed or unexpected answers all mean "no audio" and end in installed English speech. Both providers return the same in-memory `AudioClip` type, carrying only bytes and the credit of the service that supplied them, and neither persists or caches audio. One internal notice string covers both online routes and states that system speech is being used when neither answered, so no path reports a missing engine for what is only an unavailable service.
