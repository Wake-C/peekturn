# Pronunciation integration

Code paths are relative to `app/src/main/java/app/margin/reader/`.

Application-scoped `speech/PronunciationPlayer.kt` owns latest-only word-audio and system-speech playback, cancellation and audio focus; screen lifecycle events stop playback without disposing the shared player. Word audio lookup, download and preparation can fall back to installed English speech without changing the selected word. Examples/phrases never enter the word-audio lookup. Accent is a preference, not a playback gate; wrong-language voices remain unavailable. The word-audio service states no creator and no licence, so the app credits it by name and link only; the [notices](../../../THIRD_PARTY_NOTICES.md#online-word-audio) document the service, its unofficial status and Margin's lack of permission.

`speech/WordAudioProvider.kt` owns the public word-audio request: one bounded, key-free HTTPS GET per word carrying only the validated plain word and its accent parameter, with connect/read/call timeouts, a 2 MiB response ceiling, and MPEG-frame validation before anything reaches the decoder. Redirects are not followed, so a redirect answer counts as no audio and the word is never resent to whatever host the redirect names. Unavailable, redirected, oversized, malformed or unexpected answers all mean "no audio", so the caller speaks with installed English speech instead. The native decoder consumes bounded memory through a data source over the in-memory response, not an uncontrolled network address, and no downloaded audio is persisted. The shared `ui/AudioAttribution.kt` credit names and links that provider and nothing else, because it states no creator and no licence. Word-audio callbacks require both request generation and the actual player identity; failure of an obsolete TTS initialization cannot invalidate a word-audio request. Word-audio-to-speech fallback retains the same request's granted audio focus.
